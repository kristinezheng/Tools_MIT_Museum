# Repo Guide

A guide to the files in this repo. For setup steps, see [README.md](README.md) and [journal.md](journal.md).

The repo has four parts: a database dump, a physics engine, the website, and a couple of tools for making levels. Most changes to the museum game happen in `web_content/js/` and on the `playground.php` page.

## How a request flows
1. **[index.php](web_content/index.php)** gets the list of levels from MySQL and shows it.
2. Clicking a level sends the level name to **[playground.php](web_content/playground.php)**.
3. playground.php loads that level's JSON from the `trial_list` table.
4. **[PhysicsGaming.js](web_content/js/PhysicsGaming.js)** turns the JSON into a physics world.
5. **[GameWorld_DnD.js](web_content/js/GameWorld_DnD.js)** draws the world and handles the player's input.
6. When the player clicks Return, [phpcmd/record_select_data.php](web_content/phpcmd/record_select_data.php) saves what they did to `responses_tool_select`.

## Top level
| File | What it is |
|---|---|
| [tools_mit_museum.sql](tools_mit_museum.sql) | The database dump. It creates 4 tables: `trial_list` (the 58 built-in levels), `community_trial_list` (levels made in the editor), `responses_tool_select` (player data), and `trials` (older or unused). |
| [installGaming.sh](installGaming.sh) | Rebuilds `web_content/js/PhysicsGaming.js` from the Node code using browserify and minify. Only needed if `PhysicsGaming/` changes. |
| [journal.md](journal.md) | Log of the local setup. |

## `PhysicsGaming/`: the physics engine (Node)
- **[main.js](PhysicsGaming/main.js)** is the core of the game. It defines `PGWorld` (the add-object methods like `addBox` and `addBall`, plus the goal conditions) and `loadFromDict`, which turns level JSON into a world.
- `node_modules/chipmunk` is the 2D physics library it's built on. It's vendored third-party code and shouldn't need changes.
- `BKUPmain.js` is an old backup of main.js, and `testServer.js` is a dev test. `nbproject/` holds NetBeans IDE files and can be ignored.

## `ToolsGaming/` and `MakeTrials/`: making levels with scripts
- [ToolsGaming/main.js](ToolsGaming/main.js) provides `ToolPicker`. Its `Save()` method writes a level out as JSON.
- [MakeTrials/makeTrials_sample.js](MakeTrials/makeTrials_sample.js) is the example script the README walks through. It shows the standard tool shapes and how sample levels are defined.

## `web_content/`: the site PHP serves

### Pages
| Page | Purpose | Game script it uses |
|---|---|---|
| [index.php](web_content/index.php) | Home page with the list of levels | none |
| [playground.php](web_content/playground.php) | Plays one level and records the data. **This is the main game page.** | `GameWorld_DnD.js` |
| [community_levels.php](web_content/community_levels.php) / [community_playground.php](web_content/community_playground.php) | Same pair as above, but for community levels | `GameWorld_DnD.js` |
| [levelmaker.php](web_content/levelmaker.php) | The level editor | `GameWorld.js` + `builder.js` |
| [sandbox.php](web_content/sandbox.php) | Test-plays a level sent from the editor | `GameWorld.js` |
| [viewer.php](web_content/viewer.php) | Views a level without recording anything | `GameWorld.js` |

### `js/`
- **[GameWorld_DnD.js](web_content/js/GameWorld_DnD.js)** is a copy of `GameWorld.js` with drag-and-drop and touchscreen support added. Only the two play pages use it.
- [GameWorld.js](web_content/js/GameWorld.js) is the original click-to-place version. The editor, sandbox, and viewer still use it, so a change to one file doesn't carry over to the other.
- [PhysicsGaming.js](web_content/js/PhysicsGaming.js) and `.min.js` are generated by `installGaming.sh`. Don't edit them by hand.
- [builder.js](web_content/js/builder.js) contains the level editor's logic.
- [php_helpers.js](web_content/js/php_helpers.js) contains the AJAX wrappers that call `phpcmd/`. No page appears to load [php_helpers_v2.js](web_content/js/php_helpers_v2.js).
- jQuery and Bootstrap are vendored libraries.

### `phpcmd/`
Small scripts that read or write the database:
- `server.php` has the database credentials.
- `load_trial_list.php` and `load_trial.php` read levels.
- `record_select_data.php` saves player actions.
- `save_trial.php` saves a level from the editor (this is the one that checks the `cocosci` password).
- The rest (`set_progress*`, `validate_workers`, `get_flag`, `get_name`, `record_successes`) are leftovers from the online experiments. `php_helpers.js` and `builder.js` reference them, but the museum game doesn't need them.

### `css/` and `images/`
- [gwstyle.css](web_content/css/gwstyle.css) styles the game page. `builderstyle.css` styles the editor.
- `images/` has the editor and reset icons plus 40 `KidsExp_Instruct_*.png` instruction screens.

## Where to start
To change how the museum game looks or plays, start with `playground.php`, `GameWorld_DnD.js`, and `gwstyle.css`.
